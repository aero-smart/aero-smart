# 🛰️ AeroSmart 下位机通信指南 (V1.2)

本指南详细说明了 AeroSmart 项目中 **上位机服务 (Service)** 与 **下位机固件 (Firmware)** 之间，以及固件与底层传感器/执行器之间的通信机制。

---

## 1. 通信架构概览

AeroSmart 采用端到端的 Rust 协议栈，通过 **Monorepo** 结构确保协议在不同层级间的高度一致性。

*   **上位机 (Service)**: 运行于 PC/服务器，负责高层控制、数据记录与可视化。
*   **下位机 (Firmware)**: 运行于 STM32H7，负责实时控制、传感器采集与硬件抽象。
*   **共享层 (Shared)**: 定义了跨端通用的消息格式、序列化方案及数据库映射 (Scopes)。

---

## 2. 上位机 ↔ 下位机通信协议 (主协议)

### 2.1 物理层配置
*   **接口**: UART (USART1)
*   **波特率**: **915200 bps**
*   **引脚**: PA9 (TX), PA10 (RX)
*   **流控**: 无 (None)

### 2.2 握手与同步流程 (Handshake)

系统启动时必须进行一次握手，以同步时间并确认连接建立。此过程在固件 `main` 函数初始化阶段阻塞执行。

1.  **Ping (Firmware -> Service)**:
    *   固件初始化串口后，立即发送一个 `AcknowledgementData` 消息。
    *   Payload: `time_elapsed_ms` (系统启动后的毫秒数)。
2.  **Pong & Sync (Service -> Firmware)**:
    *   上位机收到 Ping 后，需回复一个 `AcknowledgementConfig` 消息。
    *   Payload: `ack = true`, `unix_timestamp_ms` (当前 UNIX 时间戳)。
3.  **Ready**:
    *   固件收到回复后，利用 `unix_timestamp_ms` 校准内部 RTC 时钟，随后启动所有异步任务 (UART RX/TX, Sensors, Control Loop)。

### 2.3 序列化方案
*   **框架**: **rkyv** (Zero-copy deserialization)。
*   **对齐**: 消息直接序列化为字节流传输，未显式使用 COBS/SLIP 封包。依赖底层传输可靠性。

## 3. 数据结构设计与 Scopes

所有通信消息封装在 `SerialMessage` 枚举中。数据结构设计不仅服务于通信，还通过 Feature Flags (如 `sql`) 定义了持久化 Scope。

### 3.1 控制指令 (Service -> Firmware)

| 消息类型 (Scope: Control) | 结构体 | 关键字段 | 说明 |
| :--- | :--- | :--- | :--- |
| **Command** | `Command` (Enum) | `Start`, `Stop`, `Calibrate` | **Start**: 进入 Running 状态<br>**Stop**: 进入 Idle 状态<br>**Calibrate**: 进入 Initializing 状态 |
| **ThrottleConfig** | `ThrottleConfig` | `airspeed` (u8) | 设定目标风速 (0-255 映射) |
| **ServoConfig** | `ServoConfig` | `angle` (u8) | 设定舵机角度 (0-255 映射) |
| **SensorConfig** | `SensorConfig` | `imu_horizontal` (bool) | 传感器安装方向配置 |
| **AcknowledgementConfig** | `AcknowledgementConfig` | `ack` (bool), `unix_timestamp_ms` (u64) | 握手与时间同步专用 |

### 3.2 遥测数据 (Firmware -> Service)

此类数据通常实现了 `to_record` 方法，支持直接映射为 SQL 数据库记录 (Scope: Persistence)。

#### 3.2.1 高频实时数据

| 消息类型 | 频率 | 结构体定义 | 数据库 Scope (Table) |
| :--- | :--- | :--- | :--- |
| **ImuData** | 20 Hz | `accel_z`, `gyro_x/y` (f32)<br>`quad_w/i/j/k` (f32, 四元数) | `imu_records` |
| **AcousticData** | 20 Hz | `overall_spl` (f32, 声压级)<br>`peak_frequency` (f32)<br>`spectral_shape` ([f32; 16], 频谱) | `acoustic_records` |
| **PitotAirspeedData** | 10 Hz | `splitter_left/right` (f32)<br>`static_port` (f32) | `pitot_records` |
| **AnalogPressureSensorData** | 10 Hz | `pressures_pa` ([f32; 4])<br>`valid_bitmask` (u8) | (待定) |

#### 3.2.2 低频监控数据

| 消息类型 | 频率 | 结构体定义 | 说明 |
| :--- | :--- | :--- | :--- |
| **LidarData** | 5 Hz | `distance_cm` (u16)<br>`signal_strength` (u16) | 激光雷达测距 |
| **ImuVibrationMetrics** | 1 Hz | `accel_z`, `gyro_x/y` (RMS, Peak, Freq) | 振动特征分析 |
| **BarometerData** | 1 Hz | `pressure_pa`, `temperature_c`, `humidity_percent` | 环境气象状态 |
| **BatteryData** | 1 Hz | `voltage_v` (f32)<br>`soc_percent` (f32) | 电源管理系统状态 |
| **QeiData** | Event | `position_counts` (u16)<br>`direction` (bool) | 旋钮/编码器交互 |
| **AcknowledgementData** | Once | `time_elapsed_ms` (u64) | 仅用于握手 Ping |

## 4. 固件 ↔ 传感器/执行器通信 (内部协议)

下位机通过硬件接口与外设交互，这些协议对上位机透明，但决定了数据的来源与精度。

### 4.1 激光雷达 (LiDAR)
*   **接口**: UART3 (PC10/PC11), 115200 bps
*   **协议**: TFmini-S 9字节定长帧 (`0x59 0x59 ...`)
*   **驱动**: `firmware/src/sensors/lidar_uart.rs`

### 4.2 空速与环境 (Pitot & Env)
*   **接口**: I2C1 (PB8/PB9), 400 kHz
*   **设备**:
    *   **MS4525DO**: 空速管差压传感器 (Addr: `0x28`)
    *   **BME280**: 温湿度气压传感器 (Addr: `0x76`/`0x77`)
*   **驱动**: `firmware/src/sensors/pitot_i2c.rs`

### 4.3 模拟气压阵列 (Analog Pressure)
*   **接口**: I2C3 (PA8/PC9), 400 kHz -> ADS1115 ADC
*   **设备**: XGZP6847A 等模拟输出传感器
*   **驱动**: `firmware/src/sensors/adc_i2c.rs`

### 4.4 惯性测量单元 (IMU)
*   **接口**: SPI1 (PB3/PB4/PB5), 1 MHz
*   **设备**: ICM-42688-P (6-Axis)
*   **驱动**: `firmware/src/sensors/imu_spi.rs`

### 4.5 动力系统 (EDF & Servo)
*   **EDF 风机**: TIM1 (PE9/PE11), **DShot600** 数字协议 (600 kHz)
*   **舵机**: TIM2 (PA0), 50 Hz PWM
*   **驱动**: `firmware/src/executors/edf.rs`, `servo.rs`

---

## 5. 调试与日志 (RTT)

*   **机制**: SEGGER RTT (Real Time Transfer)
*   **工具**: `defmt` (Logging) + `probe-rs` (Host side)
*   **用途**: 固件不占用 UART1 进行 `printf` 调试，确保通信带宽完全用于协议数据。

---

## 6. 开发注意事项

1.  **握手超时**: 上位机应在打开串口后立即监听 `AcknowledgementData`。若固件已启动，可能需发送 Reset 指令或设计重连机制（当前固件仅在启动时握手）。
2.  **数据对齐**: 由于未实现帧头同步，建议上位机在解析失败时清空缓冲区并重新尝试同步。
3.  **状态机**: 上位机需维护与固件一致的状态机 (`Idle` -> `Initializing` -> `Running`)，部分数据（如控制回路反馈）仅在 `Running` 状态下有效。
