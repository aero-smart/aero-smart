# AeroSmart Bluez BLE (GATT) 重构计划

为适配 iOS 设备 (iOS 不支持经典蓝牙 RFCOMM SPP)，我们将把蓝牙栈从 **RFCOMM** 迁移到 **BLE (Bluetooth Low Energy)**，采用通用的 **Nordic UART Service (NUS)** 方案来实现“串口透传”。

## 1. 架构变更

*   **传输层**: 从 `RFCOMM Socket` 变更为 `GATT Service`。
*   **服务定义 (NUS)**:
    *   **Service UUID**: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
    *   **RX Characteristic (App Write)**: `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` (属性: `Write` / `WriteWithoutResponse`)
    *   **TX Characteristic (App Notify)**: `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` (属性: `Notify`)
*   **协议层**: 保持原有的 `BtFrame` 协议 (Header+Len+Payload+Checksum) 不变，将其作为 Byte Stream 运行在 NUS 上。

## 2. 模块重构 (`service/src/bluetooth/`)

### 2.1 `service.rs` (核心重构)

*   **移除**: `bluer::Profile` (RFCOMM) 相关代码。
*   **新增**: `bluer::gatt::{App, Service, Characteristic}` 相关代码。
*   **逻辑变更**:
    *   **广播 (Advertisement)**: 配置 LE Advertisement，广播 NUS Service UUID，确保 iOS 能发现设备。
    *   **GATT Application**: 注册 NUS 服务。
    *   **Write Handler (RX)**: 实现 `Write` 回调，接收 App 发来的 Byte 数据 -> `try_parse_frame` -> `Converter` -> `cmd_tx`。
    *   **Notify Handler (TX)**: 维护一个 `Notify` 句柄 (或通过 `CharacteristicControl` 句柄)，当 `broadcast` 收到内部消息时 -> `Converter` -> `BtFrame` -> `to_bytes` -> 发送 Notification。

### 2.2 `codec.rs` & `converter.rs`

*   **保持不变**: 协议解析逻辑与业务转换逻辑与传输层解耦，可直接复用。

## 3. 详细实施步骤

1.  **修改 `service/src/bluetooth/service.rs`**:
    *   定义 NUS UUID 常量。
    *   重写 `run_bluetooth_service`：
        *   获取 Bluez Adapter。
        *   开启 Power。
        *   注册 `Advertisement` (包含 Local Name "AeroSmart" 和 Service UUID)。
        *   注册 `GATT Application`。
        *   建立 `mpsc` 通道或 `Arc<Mutex<...>>` 来桥接 GATT 回调与主业务逻辑。由于 `bluer` 的 GATT 回调是异步的，我们需要将 `cmd_tx` 传递给 Write Handler，并将 TX Characteristic 的 Writer 暴露给 `broadcast` 接收循环。

2.  **处理 MTU**:
    *   BLE 通知通常限制在 20 字节 (默认) 或更高 (取决于协商)。
    *   我们将尝试直接发送 `BtFrame` 的字节。如果 Frame 较长，`bluer` 或底层 Bluez 通常会自动分包，或者 App 端需要处理分包重组。鉴于 `BtFrame` 有 Header 和 Len，接收端 (App) 容易处理粘包/半包。

## 4. 验证计划

*   **编译检查**: 确保 `bluer` 的 GATT API 使用正确。
*   **逻辑验证**: 依赖原有的单元测试保证协议正确性。
*   **部署测试 (建议)**: 部署到 Linux 设备后，使用 iOS 上的 "nRF Connect" 或 "LightBlue" App 连接 "AeroSmart" 设备，订阅 TX 特征值并向 RX 特征值写入指令进行测试。
