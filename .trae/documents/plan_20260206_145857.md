# Service Implementation Plan: Serial Bridge & WebSocket

## 1. Project Structure & Dependencies
*   **Dependencies**: Ensure `service/Cargo.toml` includes `axum` (WebSocket support), `tokio` (runtime, sync), `tokio-serial` (serial port), `rkyv` (deserialization), `serde` & `serde_json` (JSON serialization for frontend), and `tracing` (logging).
*   **Architecture**:
    *   **Main Task**: Sets up channels, spawns the serial task, and runs the Axum server.
    *   **Serial Task**: Handles the physical layer (UART), handshake, and binary protocol (Rkyv).
    *   **Axum Handler**: Manages WebSocket connections, broadcasting telemetry, and forwarding commands.

## 2. Serial Communication Logic (Phase 1)
*   **Handshake**:
    *   Open the serial port (path via CLI arg, e.g., `/dev/tty.usbmodem...`).
    *   **Loop**: Read bytes looking for `SerialMessage::AcknowledgementData` (Ping).
    *   **Action**: Upon receipt, immediately send `SerialMessage::AcknowledgementConfig` (Pong) with the current Unix timestamp (`SystemTime`).
    *   **Transition**: Once handshaken, enter the main data loop.
*   **Main Loop (Uplink/Downlink)**:
    *   **Reading**: Read bytes from UART -> Deserialize `ArchivedSerialMessage` (Rkyv) -> Deserialize to Native Type -> Serialize to JSON -> Broadcast to WebSockets.
    *   **Writing**: Receive JSON command from WebSocket channel -> Deserialize to `SerialMessage` -> Serialize to Rkyv bytes -> Write to UART.

## 3. WebSocket Integration (Phase 2)
*   **Endpoint**: `GET /ws`
*   **Protocol**:
    *   **Server -> Client**: JSON string of telemetry data (e.g., `{"ImuData": {...}}`).
    *   **Client -> Server**: JSON string of control commands (e.g., `{"ThrottleConfig": {"airspeed": 100}}`).
*   **Concurrency**: Use `tokio::sync::broadcast` for fan-out telemetry and `tokio::sync::mpsc` for fan-in commands.

## 4. Implementation Details
*   **Error Handling**: No mocks. If serial fails to open or Rkyv fails to deserialize (after handshake), log error or panic as appropriate for a critical failure.
*   **Data Flow**:
    *   `Firmware` --(UART/Rkyv)--> `Serial Task` --(JSON)--> `Broadcast Channel` --(WS)--> `Frontend`
    *   `Frontend` --(WS/JSON)--> `Axum Handler` --(MPSC Channel)--> `Serial Task` --(UART/Rkyv)--> `Firmware`
